# Adding Content

**Do this first:** pick **one** letter below. Ignore the other letters until that path is done.

| You have | Open this section | Time |
| --- | --- | --- |
| New held item, trainer item, or balance text already on UNITE-DB | [A — Balance / items](#a--balance--items) | ~5–15 min |
| New Pokémon already on [unite-db.com](https://unite-db.com) | [B — New Pokémon](#b--new-pokémon) | ~20–40 min (+ clips later) |
| New move/passive video recordings | [C — Move clips](#c--move-clips) | ~10–20 min |
| Pokémon in UNITE but **not** on UNITE-DB yet | [D — Provisional](#d--provisional) | ~1–2 hr |

Hard rules (every path):

1. Never hand-edit `src/data/patch-current.json` or files named like `public/data/patch-….json`. Game data is regenerated by scripts.
2. Nothing goes live until you upload your changes with `git push` (or merge a pull request on GitHub).
3. Every ship path runs automated checks first — if something is wrong, it stops instead of shipping.

## Fixing user-facing typos

Do not edit `src/data/patch-current.json` or `public/data/patch-….json` to fix tooltip text. A later data refresh will overwrite those edits.

- **Word-level typo** (safe in every string, not a substring of a correct word): add a pair to `SPELLING_FIXES` in `tools/community/normalize.py`, add a `TestFixSpelling` assert in `tools/community/test_normalize.py`, and add the old spelling to the banned list in `src/data/__tests__/patchBundle.test.ts`.
- **Sentence-level typo** (only wrong in one move or item): add a guarded `replaceText` entry in `tools/community/patch_note_overrides.json` (`find` must be the pre-fix substring), and add that `find` to the same banned list. The `item` key resolves held items and battle items.
- Then regenerate: `npm run data:refresh -- --mode curate`.

`{0}`, `use(s)`, literal `\u201c`, and ASCII `Pokemon` are CI gates in `patchBundle.test.ts`. If you invent a number for `{0}`, you are doing it wrong — take the number from Advanced text, rewrite the sentence without a numeral, or skip.

### How to read the commands in this doc

1. **Project folder** = the `FoxForge-UNITE` directory on your computer (the one that contains `package.json`). Before any `npm …` or `git …` command, make that folder your terminal’s current directory.
2. **Check you are in the right folder:** run `pwd`. The printed path should end with `FoxForge-UNITE`.
3. **Angle-bracket placeholders are not typed literally.** Replace them, and omit the `<` and `>`:
   - `<id>` → Pokémon slug, lowercase with hyphens (example: `reshiram`, not `Reshiram`)
   - `<Name>` → display name (example: `Reshiram`)
   - `<X>` → in-game patch id (example: `1.23.3.12`)
   - `<skill-id>` → move file stem matching the game data id (example: `blue-flare`)
4. **The bare `--` in `npm run … -- …` is required.** It tells npm “options after this belong to our script, not to npm.” Example: `npm run data:refresh -- --mode curate`.
5. **“Verify”** means the automated check at the end of `npm run data:refresh` (or `npm run verify`). “Green” / “passed” = success. “Fails” = error output; stop and read it.
6. **“Ship”** means: stage files (`git add`), save a commit (`git commit`), upload (`git push`).
7. **“Drop files into a folder”** means copy or move the files there in Finder (or your editor) — not a special terminal verb.
8. **“The bundle”** = the generated game-data JSON the app loads (mainly `src/data/patch-current.json` after a refresh).

Architecture detail: [`AGENTS.md`](../AGENTS.md). Clips deep dive: [`12-adding-move-clips.md`](12-adding-move-clips.md).

## 0 — First time on this machine

**Do this now** if you have not run doctor on this Mac yet. Skip if doctor already passed today.

1. Open Terminal (or your terminal app).
2. Go to the project folder. Example if the repo lives in your home Documents area:

```bash
cd "/Users/aerokita/UNITE Build Project/FoxForge-UNITE"
```

   Use your real path if different. Confirm with `pwd` (path should end with `FoxForge-UNITE`).
3. Install/select the Node version this repo wants (files `.nvmrc` and `.node-version` both say `24`). [NVM](https://github.com/nvm-sh/nvm) must already be installed:

```bash
nvm install   # once per machine, or when the version pin changes
nvm use       # again in each new terminal tab, unless you ran: nvm alias default 24
```

4. Run the environment check:

```bash
npm run data:doctor
```

5. Fix anything it prints (Node **24+**, Python venv, ffmpeg).
6. If the `node` command is missing or too old: use NVM only (`nvm install` then `nvm use`). Do **not** try Homebrew PATH export workarounds.

**Done when:** doctor prints that the environment is ready (warnings about optional clip tools are OK if you are not doing clips).

**Next:** go to the letter you picked (A, B, C, or D).

## A — Balance / items

**You are on path A.** No hand-written builds. Pick **one** of the two options below.

### A1 — GitHub only (no laptop)

1. Open the FoxForge-UNITE repo on GitHub in a browser.
2. Click **Actions** → **Refresh game data** → **Run workflow**.
3. Optional: set `patch_version` (e.g. `1.23.3.12`) when the in-game patch id changed.
4. Wait for GitHub to open a **pull request** (a proposed change) from the branch named `data/auto-refresh`.
5. Skim the changelog in that pull request.
6. If the checks on the pull request all passed → click **Merge**. The site rebuilds from `main` automatically (GitHub Pages).
7. If checks failed because Basic move text is blank → **do not merge**. Stop path A. Open [B — New Pokémon](#b--new-pokémon).
8. If checks failed for another reason → stop and fix the error before merging.

**Done when:** pull request merged (or you switched to B).

**Next:** open the live site and spot-check an affected item/Pokémon, or stop.

### A2 — Terminal

1. Open Terminal and go to the project folder (`pwd` should end with `FoxForge-UNITE`).
2. Refresh game data. If the in-game patch id did **not** change, omit `--patch-version …` entirely:

```bash
npm run data:refresh -- --patch-version 1.23.3.12
```

   (Put the real patch id where `1.23.3.12` is in this example.)
3. Watch the end of the output. If **verify** fails on blank Basic descriptions → stop path A. Open [B — New Pokémon](#b--new-pokémon).
4. If **verify** fails for another reason → stop and read the error.
5. Save and upload:

```bash
git add -A
git commit -m "chore(data): refresh UNITE data"
git push
```

**Done when:** `git push` succeeded and GitHub Actions / Pages looks successful.

**Next:** open the live site and spot-check, or stop.

## B — New Pokémon

**You are on path B.** ~20–40 minutes once UNITE-DB has the Pokémon (longer if you also add clips).

Hand work is usually:

1. Basic move/passive text if UNITE-DB left them blank
2. One Recommended build
3. Optional app version bump
4. Optional clips

Before any command below: your terminal’s current directory must be the `FoxForge-UNITE` project folder (`pwd` ends with `FoxForge-UNITE`). Commands are not “inside” that folder as a list — you run them **while you are in** that folder.

Replace placeholders as in [How to read the commands](#how-to-read-the-commands-in-this-doc).

### B — Do now

1. Download latest UNITE-DB data into the project (include `--patch-version …` when the in-game patch id changed):

```bash
npm run data:refresh -- --patch-version 1.23.3.12
```

2. If this fails **verify** on blank Basic descriptions → that is expected for many launches. Continue to step 3. If it fails for another reason → stop and read the error.
3. List what is still missing:

```bash
npm run data:gaps
```

4. Read the lines for your Pokémon’s `<id>` (example: `reshiram`). Typical leftovers: no Recommended builds, blank descriptions, missing clips.
5. When `data:gaps` or **verify** says Basic text is blank: open `tools/community/move_descriptions.json` in your editor and add a JSON object keyed by `"<id>"`.
6. Inside that object, keys are **normalized** move/passive names: lowercase, strip trailing `(…)` and apostrophes (`Sirfetch'd` → `sirfetchd`). Example:

```json
"reshiram": {
  "turboblaze": "Has the user …",
  "dragon breath": "Has the user …",
  "blue flare": "Has the user …\n\nUpgrade (Level 13): …"
}
```

7. When writing Basic text:
   - Copy in-game Basic tooltip text (Switch/mobile tooltip, or a PNG still under `screenshot-references/move-descriptions/<id>/`). Do not paste another website as the live source.
   - Keep `\n\n` between paragraphs.
   - Prefer `Upgrade (Level N):` using the upgrade’s second level from UNITE-DB (`level2`, often 10, 11, 12, or 13). The yellow in-game banner **Once you reach Lv. N** and the UI **Lv N** chip are the **learn** level, not the Upgrade level. Stills usually show a bare `Upgrade:` — do not copy the learn number into `Upgrade (Level N):`. Keep a number that was already correct in the archive.
   - If Basic already has body text but no Upgrade line, the **normalize** script (part of refresh) will copy **only** the Advanced Upgrade paragraph automatically — you do not need to paste numbers by hand.
   - No `attack` key needed unless you have basic-attack Basic text (basic attacks are excluded from the blank-description check).
   - If the app still shows a pre-evolution Ability name (Eevee Adaptability, Larvitar Guts, …), add that Pokémon’s UNITE-DB `name` slug to `PLAYABLE_PASSIVE_SLUGS` in `tools/community/normalize.py`. Do not add `mew`. Do not add mega-license slugs. Then run curate + `fetch_art.py` (not a full harvest). See [`13-in-game-basic-text.md`](13-in-game-basic-text.md).
8. Create a Recommended-build template for this Pokémon:

```bash
npm run data:curate -- scaffold reshiram --write
```

   (Use your real `<id>` instead of `reshiram`.)
9. Open `tools/community/curated_builds.json`, find that `"<id>"` entry, and fill:
   - `name` / `emblemName` (same string is fine)
   - `lane` (e.g. `Anywhere Damage` or `Path Damage`)
   - `heldItemIds` (three ids, e.g. `energy-amplifier`)
   - `battleItemId` (e.g. `eject-button`)
   - `emblems` (exactly 10 × `{ "emblemId": "048-venonat", "grade": "gold" }`)
   - `moves` (the two **final** move names from the scaffold `_comment`)
10. Validate the curation file:

```bash
npm run data:curate -- check
```

11. Fix anything it reports (it suggests nearby ids for typos).
12. Rebuild game data using your curation (skips a full UNITE-DB re-download):

```bash
npm run data:refresh -- --mode curate
```

13. Confirm this finished with **verify** passed. If not → stop and fix before shipping.
14. Re-check gaps:

```bash
npm run data:gaps
```

15. Confirm your `<id>` no longer lists blank descriptions or missing builds. Missing clips are OK for ship.
16. Bump the app version shown in Settings → App version. New Pokémon on the roster → bump the **minor** number (e.g. `2.3.1` → `2.4.0`). Tiny follow-up with no roster add → bump **patch** (e.g. `2.4.0` → `2.4.1`):

```bash
npm version 2.4.0 --no-git-tag-version
```

17. Update the “currently `x.y.z`” / roster / `patchVersion` sentences in `AGENTS.md` if they still show the old numbers.
18. Save and upload to `main`:

```bash
git add -A
git commit -m "feat(data): add Reshiram — patch 1.23.3.12 (v2.4.0)"
git push origin main
```

   (Swap in your real `<Name>`, patch id, and version in the message.)
19. Quick check on the live site (or run `npm run dev` first and open the local URL it prints):
    - Picker shows the Pokémon
    - Recommended build applies
    - Basic/Advanced tooltips look right
    - Settings shows the new game-data and app versions

**Done when:** push is up and the check above passes. Clips can wait.

**Next (optional):** if you already copied recordings into the clips folder, do steps B20–B22. Otherwise stop, or open [C](#c--move-clips) later.

### B — Optional clips (same session or later)

20. Copy raw video files into `tools/community/_clips/<id>/` (see [`12-adding-move-clips.md`](12-adding-move-clips.md)).
21. Run a clips-only refresh (required even if you already ran a full refresh — full mode processes videos *before* the new Pokémon exists in the bundle):

```bash
npm run data:refresh -- --mode clips
```

22. Save and upload media if you did not already in step 18 (`git add -A`, `git commit`, `git push`).

### B — Footguns (read once before/during B)

1. Never hand-edit `patch-current.json` or `public/data/patch-….json`.
2. Blank Basic text fails automated checks — fill `move_descriptions.json`, then run `--mode curate`. Closing a failed auto-refresh pull request and doing section B is normal.
3. `builds` vs `recommendedTitles` are mutually exclusive per Pokémon. New mons use `builds`.
4. Scaffold needs the Pokémon already in the bundle — run B step 1 before B step 8.
5. Clips after adding a Pokémon — always finish with `--mode clips` if you copied recordings in.

## D — Provisional

**You are on path D.** Use only when the mon is playable in UNITE but missing from `https://unite-db.com/pokemon.json`. Hard path (~1–2 hours). Precedent: Palkia.

### D — Phase A (ship a placeholder)

1. In Terminal, go to the `FoxForge-UNITE` project folder.
2. Append rows to `tools/community/_raw/pokemon.json` and `tools/community/_raw/stats.json` (copy stats from a similar mon; leave `rsb` empty; use a temporary numeric `id` of 900 or higher).
3. Add Basic text in `move_descriptions.json`.
4. Add curated `builds` using [B steps 8–15](#b--do-now) (scaffold → fill → check → `--mode curate` → gaps).
5. Add placeholder art files at both:
   - `public/assets/pokemon/portrait/<Name>.png`
   - `public/assets/pokemon/thumbnail/<Name>.png`
6. Write `tools/community/_raw/<NAME>-PROVISIONAL.md` listing what is fake (example name: `PALKIA-PROVISIONAL.md`).
7. Rebuild from curation:

```bash
npm run data:refresh -- --mode curate
```

8. Prefer that single command. Only if you are deliberately running pipeline pieces yourself: normalize → presets → art → publish → verify (same end state as the command above).
9. Save and upload with `git add` / `git commit` / `git push`. For clips, follow [`12-adding-move-clips.md`](12-adding-move-clips.md).

**Done when (Phase A):** placeholder is on `main` and marked provisional in `_raw/`.

**Next:** stop until UNITE-DB catches up, then do Phase B.

### D — Phase B (when UNITE-DB catches up)

1. Delete the placeholder art files and the `*-PROVISIONAL.md` file.
2. Pull real data (this overwrites `_raw` and refreshes art):

```bash
npm run data:refresh -- --patch-version 1.23.3.12
```

3. Re-check `move_descriptions.json` keys against the real move names.
4. List leftovers and fix them:

```bash
npm run data:gaps
```

5. Bump the app version (`npm version … --no-git-tag-version` as in B step 16).
6. Save and upload (`git add` / `git commit` / `git push`).

**Done when (Phase B):** no provisional files left; real UNITE-DB data is live.

**Next:** quick-check the Pokémon on the live site or with `npm run dev`.

## Command cheat sheet

Use while mid-path. Skip if you already know the command. All of these assume your terminal is already in the `FoxForge-UNITE` project folder.

| Command | When |
| --- | --- |
| `npm run data:doctor` | First step on a new machine |
| `npm run data:refresh` | Full pull from UNITE-DB (+ verify) |
| `npm run data:refresh -- --patch-version X` | Full pull and set game-data patch id |
| `npm run data:refresh -- --mode curate` | After editing builds or descriptions |
| `npm run data:refresh -- --mode clips` | After copying in new recordings |
| `npm run data:gaps` | “What is still missing?” |
| `npm run data:curate -- scaffold <id> --write` | Insert build template |
| `npm run data:curate -- check` | Validate `curated_builds.json` |
| `npm run verify` | Run the full local check suite (same idea as CI on GitHub) |
| `npm version X.Y.Z --no-git-tag-version` | Bump Settings app version |

Refresh modes:

1. `full` (default) = doctor → fetch → transcode → normalize → presets → harvest → art → boosts → publish → verify
2. `curate` and `clips` run smaller subsets of that list

## Reference — Descriptions

Skip while executing A–D. Open when writing Basic text.

1. **Advanced** — from UNITE-DB (`rsb` field); filled in automatically.
2. **Basic** — from UNITE-DB when present; otherwise from `tools/community/move_descriptions.json`.
3. After your archive text is applied, the **normalize** script punctuates Basic paragraphs and appends Advanced’s Upgrade paragraph onto Basic when Basic lacks an Upgrade marker.
4. After editing the archive → `npm run data:refresh -- --mode curate`.

---

## Reference — Curated builds

Skip while executing A–D. Open when editing builds.

Only edit [`tools/community/curated_builds.json`](../tools/community/curated_builds.json).

1. Never hand-edit `emblemName` (or anything else) in the generated patch JSON files.
2. Per Pokémon: `builds` **or** `recommendedTitles`, not both. `creativeBuilds` may coexist.
3. After build edits, run `--mode curate` (or `npm run generate:presets`) — automated checks fail if `emblemOptimizerPresets.json` is stale.

## Reference — Publish + verify

Skip while executing A–D. Open when debugging publish/manifest mismatches.

| Copy | Path |
| --- | --- |
| Build-time baseline | `src/data/patch-current.json` |
| Published runtime | `public/data/patch-<patchVersion>.json` + `manifest.json` |

1. `manifest.json` `version` must equal the bundle’s `lastUpdated`.
2. `npm run data:refresh` / `npm run data:publish` keep them aligned.
3. Confirm with `npm run verify`.
4. Balance-patch watch list: [`10-patch-watch-checklist.md`](10-patch-watch-checklist.md).
